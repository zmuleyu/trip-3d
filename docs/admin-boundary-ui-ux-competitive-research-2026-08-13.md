# 行政区划图层 UI/UX 竞品研究与方案讨论（2026-08-13）

> 范围：研究与方案讨论，不在本 Goal 中直接改 UI。资料优先取热门产品官方文档；Web 搜索后端当次不可用，改为浏览器直读官方页面，不使用二手营销稿作结论。

## 1. 竞品模式

### Google Maps Platform：Feature Layer + hover/click 状态

- 将国家、一级行政区、二级行政区、城市、邮编等拆成独立地图项图层。
- 支持分别设置 fill、fill opacity、stroke、stroke opacity、stroke weight。
- 官方事件示例明确区分三态：默认、`mousemove`（边框加粗）、`click`（填充着色并显示 InfoWindow）。
- 只有可见要素才能接收事件，因此其示例要求默认 fill opacity 至少 0.1。

启示：行政区不是“一张静态线网”，而是具有默认 / hover / selected 状态的可查询要素；但 trip-3d 不能直接复制点击行为，因为地图点击同时承担规划打点。

来源：
- [Google：边界数据驱动样式概览](https://developers.google.com/maps/documentation/javascript/dds-boundaries/overview)
- [Google：处理边界鼠标事件](https://developers.google.com/maps/documentation/javascript/dds-boundaries/handle-events)

### Mapbox Boundaries：层级、唯一 ID、元数据与 worldview

- 全球边界按多种 layer type 和行政层级组织；几何使用优化过的矢量瓦片。
- 几何只保留唯一 ID 和少量属性，名称翻译、行政层级和代码等元数据通过 lookup tables 关联。
- 明确支持 disputed areas 的 worldviews；同时强调本地名称、翻译、层级关系和代码。
- 边界用于搜索、区域分析、自定义区域和业务数据连接，不只是装饰线。

启示：UI 应显示层级与父子链，选中状态应有稳定 `adcode`；数据来源、覆盖范围与争议边界语义必须可见，不应让用户误以为边界是绝对法律结论。

来源：
- [Mapbox Boundaries 官方指南](https://docs.mapbox.com/data/boundaries/guides/)

### 高德 DistrictLayer：深度、缩放范围、分级线型

- 官方提供 World / Country / Province 三类简易行政区图层。
- API 将 `adcode`、`SOC`、`depth`、`zooms`、`opacity`、`visible`、`zIndex` 作为一等参数。
- 样式明确拆为 nation / province / city / county stroke，并允许逐层设置颜色；支持 show/hide、opacity、zoom range。

启示：最成熟的控制不是多个“省/市/县”开关，而是一个图层开关 + 层级深度 + 自动缩放策略；线型必须体现层级，不只靠颜色。

来源：
- [高德 JSAPI 2.0：AMap.DistrictLayer](https://a.amap.com/jsapi/static/doc/index.html#districtlayer)

### CesiumJS：3D Entity 统一表达

- Entity API 统一表达 polygon、polyline、label 等空间对象，强调数据展示与信息聚合，而不是暴露底层图形机制。
- polygon 原生支持透明填充和 outline；实体可与标签及其他属性组合。

启示：trip-3d 当前 `Line + Sprite` 可继续使用，但交互层应把一个行政区视为统一对象（边界、标签、名称、adcode、父级），不要让线和标签成为互不关联的图元。

来源：
- [CesiumJS：Creating Entities](https://cesium.com/learn/cesiumjs-learn/cesiumjs-creating-entities/)

## 2. 当前 trip-3d 的主要 UX 问题

1. **开关只有开/关，没有层级语义**：用户不知道当前看到的是省、市还是县。
2. **零段状态容易被误解**：z12 处于单一旗县内部时“0 段”地理上正确，但用户会认为加载失败。
3. **行政省界使用橙色，与路线主色竞争**：路线是核心任务，行政区只能是辅助背景。
4. **白底行政标签与 POI 标签同形**：两种语义难区分，也加剧视觉拥挤。
5. **如果直接加入 click 选区，会抢占规划打点**：这是 trip-3d 相比普通 GIS 最大的交互约束。
6. **成功状态依赖 toast**：toast 消失后，用户不知道数据层级、数据源、缓存状态和当前区域。
7. **深度选择与缩放未绑定**：高 zoom 下省/市边界可能根本不穿过视口，需要自动下钻和“当前位于”提示。

## 3. 推荐方案：渐进披露 + 独立“查看区划”模式

### 3.1 保留 rail 快捷开关，但增加二级面板

单击 `🏛`：立即开/关图层，保持快速操作。

再次单击已开启按钮，或长按/右键：打开紧凑图层卡：

```text
行政区划                         [开]
当前：内蒙古自治区 / 乌兰察布市 / 察哈尔右翼后旗
层级： [自动]  省  市  县
标签： [智能]  关
查看区划详情                    [进入]
── 图例 ─────────────────────────
━━ 省界   ── 市界   - - 县界
数据：DataV · 中国范围 · 已缓存
```

- 默认使用“自动”，不要首次开启就要求选择层级。
- 面板默认收起图例和来源；只有用户需要时展开。
- 当前区域 breadcrumb 即使没有边界穿过视口也必须显示。

### 3.2 自动层级不是简单 zoom 阈值，而是“可见边界优先”

建议策略：

- 先按 zoom 给出目标层级：远景省、中景市、近景县。
- 如果目标层级没有边界穿过当前视口：仍显示当前行政区名称，并自动尝试下钻一级。
- 若下钻后仍无边界：显示“当前视图完全位于察哈尔右翼后旗内；缩小地图可查看边界”，而不是“0 段”。
- 手动层级选择覆盖自动策略，但要提示该层级在当前视口无边界。

### 3.3 展示与拾取必须分模式

**普通/规划模式**：
- 行政区只展示，不接管地图 click。
- hover 可弱提示，但不得阻止打点；触屏不启用 hover。
- 点击地形继续添加/编辑路线点。

**查看区划详情模式**：
- rail 按钮与面板显示明确的“查看中”状态，地图 cursor 改为查询态。
- hover：仅加粗当前边界、显示临时名称。
- click：选中行政区，添加 6–10% 低透明填充，并显示详情卡。
- Esc、再次点“查看中”或进入规划动作时退出查询态。

这比“图层开启后所有点击都选区”安全，避免与主任务冲突。

### 3.4 视觉层级

路线必须始终高于行政区：

| 元素 | 建议 |
|---|---|
| 路线 | 保留橙色主色、最高视觉权重 |
| 省界 | 冷色蓝 `#48A9FF`，1.5px 等效、实线 |
| 市界 | 冷白/浅蓝，1px、实线、较低透明度 |
| 县界 | 冷灰蓝，0.75px、虚线 |
| hover | 线宽约 1.7×，不填充或 3% 填充 |
| selected | 2–2.5px + 6–10% 冷色填充 |
| 行政标签 | 无白盒常态：文字 + 深色 halo；仅 selected 使用小型 pill |

- 不用橙色行政线：橙色继续留给路线、主动作和 rail 激活态。
- 不只靠颜色区分省/市/县，要同时使用线宽和虚实。
- 标签进入现有冲突控制：路线 > 途经点 > 当前选中行政区 > 普通行政标签 > POI。
- 巡演/飞越 `focus-mode` 默认隐藏行政标签和详情卡；边界是否保留可独立设置，默认隐藏。

### 3.5 选中详情卡应服务“旅行规划”，不是复制 GIS 属性表

```text
察哈尔右翼后旗
内蒙古自治区 · 乌兰察布市
行政代码 150928
路线：进入 2 次 · 预计途经 38 km       （有路线时）
[聚焦此区域]  [添加为搜索范围]
```

第一阶段只需：名称、父级链、adcode、“聚焦此区域”。路线交叉统计与区域内搜索属于后续增强，避免过度实现。

### 3.6 状态与异常

- 加载中：rail 图标内部微型 spinner；不弹持续 toast。
- 成功：图层卡显示“已缓存 / 刚更新”；成功 toast 可取消。
- 境外：面板显示“中国范围外暂不可用”，并提供未来 Natural Earth 覆盖说明；不要只把按钮弹回。
- 网络失败且有过期缓存：可考虑“使用旧缓存”并显示更新时间（当前实现严格 TTL 后回源，未来可做 stale-while-revalidate）。
- 数据源与覆盖范围常驻在图层卡底部，解决可信度问题。

### 3.7 移动端

- rail 行政按钮打开 bottom sheet，不使用 hover。
- “显示边界”和“查看区划”是两个明确动作。
- 查看模式下单击选区；返回键/下滑关闭并恢复路线交互。
- 图例压成一行；层级使用 segmented control。

### 3.8 可访问性

- 图层按钮使用 `aria-pressed`；查询模式使用明确文本，不只靠颜色。
- 省/市/县以线宽和虚实双编码。
- 选中详情卡可被键盘聚焦，Esc 退出。
- 行政标签需要独立于画布的可读名称出口（详情卡/状态文本），不能只存在于 WebGL sprite。

## 4. 可选方案与权衡

### A. 推荐：快捷开关 + 紧凑图层卡 + 独立查看模式

- 优点：兼顾普通用户和高级查询；不会破坏规划打点；移动端可映射。
- 代价：需要明确 mode 状态和行政区拾取。

### B. 极简：只做自动层级、当前区域提示、视觉换色

- 优点：改动小，最快降低困惑和视觉冲突。
- 缺点：行政区仍不可查询，价值停留在背景参考。

### C. GIS 化：完整图层树、独立透明度、每级开关、属性表

- 优点：能力最强。
- 缺点：与旅行规划产品定位不符，面板和认知负担过重；当前不建议。

## 5. 建议实施波次（待用户拍板后另开 UI Goal）

1. **L2-UX 基础**：当前区域 breadcrumb、自动层级、零边界正确提示、行政线改冷色、标签 halo、成功状态进入图层卡。
2. **L2-Inspect**：独立查看模式、hover/selected、详情卡、Esc/模式仲裁。
3. **L2-Mobile/A11y**：bottom sheet、触屏选择、键盘和 screen-reader 状态。
4. 可选：路线穿越行政区统计、按行政区限定搜索、境外 Natural Earth/worldview。

## 6. 需要用户拍板

- 选择 A（推荐）、B（极简）或 C（GIS 化）。
- 行政边界是否接受改为冷色蓝，彻底给路线让出橙色主视觉。
- 查询详情首版是否只做名称/父级/adcode/聚焦，还是同时做“路线穿越统计”。
